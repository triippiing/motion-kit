# Sync Page (C1) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A browser sync page (`sync.mjs DIR`) where the user checks the beat grid by ear against the song and the live animation, nudges it, taps the tempo, sets meter and swing, marks named moments, and saves them into `song.json`. Tables can then hit those moments with `at: 'name'`.

**Architecture:**
- **Timing.** One pure timing module (`components/core/timing.js`) defines musical time: `beatTime` (interpolation with swing), marker beats and table-row resolution. Every consumer uses it.
- **Analyser.** `analyze_song.py` owns a user section `sync` in `song.json`. It preserves that section, applies it, and re-cuts `clip.wav` from the original song, whose path is kept in a git-ignored `.source.json`.
- **Server.** `sync.mjs` adds two routes to render.mjs's existing `serve()`: the page and a save endpoint.
- **Page.** It plays `clip.wav` through Web Audio, schedules clicks on the audio clock, and drives the project's own page in an iframe through `seek(t)`.

**Tech Stack:** Node (ES modules, `node:test`), Playwright (already pinned), Python 3 + numpy (analyser), plain HTML/CSS/JS for the page (no frameworks), ffmpeg.

**Spec:** `docs/superpowers/specs/2026-10-01-sync-page-design.md`

## Global Constraints

- **Old projects don't move.** A song with no `sync` section must give identical beat and half-beat times to today's, within 1e-6 s. This applies to the fixtures and to demos 01, 02 and 04.
- **`sync` field ranges.** `nudge_ms` is a number. `bpm` is null or a number from 40 to 240. `meter` is one of `4/4`, `3/4`, `6/8`. `swing` is from 0.5 to 0.75. Each marker is `{ name, t }`, where name matches `^[a-z][a-z0-9-]*$`, names are unique, and `t` is in song seconds.
- **The ear wins.** When `nudge_ms != 0` or `bpm` is set, `cue_t` equals the grid time, with no onset snapping.
- **Markers don't follow the nudge.** A nudge never moves markers.
- **Privacy.** `song.json` keeps only the song's basename. The absolute path lives only in `DIR/.source.json`, which must never be committed (git-ignored).
- **Server.** The sync server binds 127.0.0.1 only. Save writes only `song.json`, `song.json.bak`, `clip.wav` and `.source.json` inside DIR.
- **Errors.** Scripts print `error: ...` and exit 2 on bad input, never a traceback. The realpath entry guard stays on every CLI.
- **Dependencies.** No new Node or Python dependencies. Node >= 20.11. Use ffmpeg and ffprobe from /opt/homebrew/bin.
- **Prose.** No em dashes or en dashes in new prose. SKILL.md commands must be exact.
- **Music.** Never commit audio, renders or `out/`. Never download music.

```js
// timing.js: the one definition of musical time, shared by the page, the engine, the scripts and the sync page.
// Pure, no DOM; an ES module that runs in the browser and in Node. Projects get their own copy with components/.

// Swing: where the off-beat lands inside a beat. Piecewise linear through (0,0), (0.5, swing), (1,1).
export const warp = (f, swing = 0.5) => (f <= 0.5 ? f * (swing / 0.5) : swing + (f - 0.5) * ((1 - swing) / 0.5));
export const unwarp = (u, swing = 0.5) => (u <= swing ? u * (0.5 / swing) : 0.5 + (u - swing) * (0.5 / (1 - swing)));

const last = (song) => song.beats.length - 1;
// Grid time of beat i (t), extended by beat_sec past either end.
function grid(song, i) {
  const n = last(song);
  if (i < 0) return song.beats[0].t + i * song.beat_sec;
  if (i > n) return song.beats[n].t + (i - n) * song.beat_sec;
  return song.beats[i].t;
}
// Where beat i sounds: its measured cue (cue_t), else its grid time.
const start = (song, i) => song.beats[i]?.cue_t ?? grid(song, i);

// Loop time (seconds) of beat b (fractional allowed).
export function beatTime(song, b) {
  if (!song.beats?.length) return b * song.beat_sec;
  const i = Math.floor(b), f = b - i;
  const t0 = start(song, i);
  return f === 0 ? t0 : t0 + warp(f, song.sync?.swing ?? 0.5) * (grid(song, i + 1) - grid(song, i));
}

// Fractional beat at loop time t: the inverse of beatTime.
export function beatAt(song, t) {
  if (!song.beats?.length) return t / song.beat_sec;
  let i = 0;
  while (i < last(song) && start(song, i + 1) <= t) i++;
  if (t < start(song, 0)) i = Math.floor((t - start(song, 0)) / song.beat_sec);
  const span = grid(song, i + 1) - grid(song, i);
  return i + unwarp(Math.min(1, Math.max(0, (t - start(song, i)) / span)), song.sync?.swing ?? 0.5);
}
```

**The page (layout B, per the spec):**
- **Left:** the iframe, square, scaled to fit.
- **Right, top:** the waveform canvas. It shows about 2 bars around the playhead and scrolls with it.
  - Bars are drawn as 2 px lines and beats as 1 px lines at 40% opacity.
  - Swung half-beats appear at 20% when swing ≠ 0.5.
  - Markers are orange flags with labels, draggable. Delete or right-click removes one.
  - Wheel scrolls, Ctrl+wheel zooms (between 0.5 and 8 bars visible), and a click sets the playhead.
- **Right, below:** an overview strip of the whole loop, with a draggable window.
- **Controls:**
  - Play
  - Nudge readout (`-18 ms`)
  - Tap readout (`109.0 BPM`, plus the tapped value)
  - Meter select
  - Swing slider (0.5 to 0.75, step 0.01)
  - Clicks toggle
  - "Sounds right"
  - Save
  - Status line: confidence, "unsaved changes", the last save time and errors from the server
- **Keys:**
  - Space: play/stop.
  - ← / →: nudge ±5 ms; with Shift, ±20 ms.
  - T: tap. Average the intervals of the last 8 or more taps and show the BPM; Enter applies it to `sync.bpm`.
  - M: add a marker at the playhead, with an inline name prompt; the name must match the name rule.
  - C: clicks on or off.
  - Ctrl+S: save.
- **Clicks.** The page creates short click buffers (downbeat 1.5 kHz, others 1 kHz, 20 ms decay). Each click is scheduled with `AudioBufferSourceNode.start(when)` about 100 ms ahead of `currentTime`, at the grid's (preview) beat times.
