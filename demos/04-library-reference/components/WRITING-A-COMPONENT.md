# Writing a component

A component is one file that draws one kind of UI inside the kit's single morphing shape: a button,
a toggle, a chart. Once it exists, anyone can put it in a video with one table row
(`{ at: 4, use: 'tag', label: 'Design' }`) and aim the cursor at it (`{ at: 5, target: 'tag', press: true }`).

This guide is everything you need: what the engine gives you, a complete working component to copy,
the rules the tests and reviews hold every component to, and the steps to ship it.

Paths are relative to the `motion-video` skill folder (`<clone>/skills/motion-video/`, or
`~/.claude/skills/motion-video/` after `install.sh`).

## Where things live

| Path | What it is |
|---|---|
| `components/<group>/<name>.js` | one component; `<group>` is `controls`, `feedback`, `data` or `chrome` |
| `components/core/engine.js` | runs the tables: layers, continuations, presses, cursor, camera. Its header comment is the contract |
| `components/core/helpers.js` | pure building blocks every component uses (list below) |
| `components/core/validate.js` | the rules a table is checked against (runtime and `check_brief.mjs`) |
| `components/index.js`, `components/CATALOG.md` | GENERATED by `scripts/build_catalog.mjs` from each component's `meta`; never edit by hand |
| `components/docs-images/<name>.png` | the catalog thumbnail, made by `scripts/gallery.mjs --stills` |
| `controls/button.js` | the reference component; read it next to this guide |

## How the engine uses a component

For every table row with `use: '<name>'` the engine:

1. fills in the row's props from your `meta.props` defaults (a key the row leaves out gets the default);
2. calls `geometry(props, ctx)` once to size the shape (`w`, `h`, corner radius `r`, `fill`, `ink`);
3. makes a `.layer` div inside the shape and calls `mount(layer, props, ctx)` once to build the DOM;
4. on every frame calls `render(layer, props, ctx, t)`, which sets styles, attributes and text from `t`;
5. resolves each cursor row aimed at one of your hotspots with `hotspot(name, props, geo, ctx)`.

The engine does the rest: it morphs the shape between rows, fades whole layers in and out between
different components, drives the camera and cursor, and plays the click for every press.

### The module contract

```js
export const meta = {
  name: 'tag',              // the file name without .js; what rows write as use:
  group: 'controls',        // the folder it lives in
  useWhen: '...',           // one line: when to pick it (the planner matches moments on this)
  motion: '...',            // what moves and how, including what presses and continuations do
  props: { label: ['string', 'Design'] },   // key: [type, default]; types below
  hotspots: ['tag'],        // cursor targets; a family is written 'item:<label>'
  sounds: [],               // sounds it plays itself (e.g. ['key'])
  example: "{ at: 0, use: 'tag', label: 'Design' }",   // ONE line, used in the catalog and tests
  edgeCases: [{ label: '' }],                          // rows (without at/use) that push the limits
  hotspotExample: { 'item:<label>': 'item:Plan' },     // only if a hotspot is a family: one real name
  drag: ['thumb'],          // only if a hotspot is dragged (you read ctx.cursorAt): which ones; validate then
                            // warns when a drag on it never moves the cursor between the 'down' and the 'up'
};
export function geometry(props, ctx) { return { w, h, r, fill: 'surface', ink: 'ink' }; }
export function mount(layer, props, ctx) { /* build DOM once */ }
export function render(layer, props, ctx, t) { /* set styles from t, every frame */ }
export function hotspot(name, props, geo, ctx) { return { x, y } /* offset from the shape centre */ ?? null; }
export function sfx(props, ctx) { return [{ beat, file, gain }]; }   // optional: its own sounds
export function endState(props, ctx) { return { ...props, ... }; }   // optional: props after the presses
```

Prop types: `string`, `number`, `boolean`, `string[]`, `number[]`, `object`, `object[]`, `any`, and
`enum:a|b|c`. A row that passes the wrong type fails validation with a readable message.

### What is in `ctx`

| Field | Meaning |
|---|---|
| `t0`, `t1` | this row's start and end in seconds (`t1` is `Infinity` for the last row). Row 0's `t0` is -1e6: see "Row 0 is settled" |
| `settled` | true for row 0, which is shown with its entrance long finished |
| `continues`, `prev` | true, and the previous row's end state, when the row before this one used the same component (a continuation) |
| `presses` | the cursor presses routed to this row: `{ t, kind, hotspot }`, kind `true`, `'down'` or `'up'` |
| `targets` | every cursor row aimed at this row's hotspots (`{ t, target, press }`) plus, as `target: null`, every other cursor row inside its window; in time order |
| `cursorAt(t)` | the cursor's position in design px from the stage centre (for drags) |
| `geo` | this row's resolved `w`, `h`, `r`, `fill`, `ink` (a row can override geometry) |
| `row` | the raw table row (`row.at` is its beat) |
| `beat_sec`, `beatT(beat)` | seconds per beat, and a beat number to seconds on the song's measured grid |
| `Springs`, `spring` | the spring maths, and the house spring from the song |
| `theme`, `hex(role)` | the theme's colour roles, and a role to `[r, g, b]` |
| `stage`, `loop_sec` | the stage size, and the loop length in seconds (null when the piece does not loop) |

## A complete component to copy

`tag` below is a working component (the test suite loads this exact block and checks it against the
contract). It shows the patterns you will need most: a press that changes state, `endState`, a
continuation that carries on from the previous row, a crossfade of changed content, and the press dip.
Copy it to `components/<group>/<name>.js` and change it.

```js
// tag.js -- a label chip that a press selects or deselects.
import { el, textW, pressesOn, pressDepth, fade, applyFade } from '../core/helpers.js';

export const meta = {
  name: 'tag', group: 'controls',
  useWhen: 'A label is picked or dropped: a topic, a filter, a category.',
  motion: 'A press on the tag dips it and selects it (or deselects it): the fill blends to the accent. A following tag row continues from where the presses left it (write the pressed result as its `selected`) and blends on arrival if its `selected` differs; a changed label crossfades.',
  props: { label: ['string', 'Design'], selected: ['boolean', false] },
  hotspots: ['tag'],
  sounds: [],
  example: "{ at: 0, use: 'tag', label: 'Design', selected: true }",
  edgeCases: [{ label: '' }, { label: 'A very long tag name that keeps on going and going' }],
};

const PAD = 40;
export function geometry(p) {
  return { w: Math.min(1200, Math.max(160, PAD * 2 + textW(p.label, 28, 400))), h: 88, r: 44, fill: 'surface', ink: 'ink' };
}

// Selected over time: where the row starts (the previous row's end when continuing), a change on
// arrival if this row says otherwise, then one flip per press on the tag ('up' is not a new press).
function plan(p, ctx) {
  let on = ctx.continues ? ctx.prev.selected : p.selected;
  const from = on, events = pressesOn(ctx, 'tag').filter((x) => x.kind !== 'up').map((x) => ({ t: x.t }));
  if (on !== p.selected) events.push({ t: ctx.t0, set: p.selected });
  const changes = [];
  for (const ev of events.sort((a, b) => a.t - b.t)) {
    on = 'set' in ev ? ev.set : !on;
    changes.push({ t: ev.t, to: on ? 1 : 0 });
  }
  return { from, changes, on };
}

// The row as it stands after its presses: a following tag row starts from here (ctx.prev).
export const endState = (p, ctx) => ({ ...p, selected: plan(p, ctx).on });

function label(parent, p, cls) {
  const s = el(parent, 'span', { class: `tag-label ${cls}` }, p.label);
  Object.assign(s.style, { gridArea: '1 / 1', font: '400 28px var(--font)' });
}
const changed = (a, b) => a.label !== b.label;

export function mount(root, p, ctx) {
  Object.assign(el(root, 'div', { class: 'tag-bg' }).style, { position: 'absolute', inset: '0' });
  const box = el(root, 'div', { class: 'tag-box' });
  Object.assign(box.style, { display: 'grid', placeItems: 'center' });
  if (ctx.continues && changed(ctx.prev, p)) label(box, ctx.prev, 'tag-prev');
  label(box, p, 'tag-cur');
}

export function render(root, p, ctx, t) {
  const bs = ctx.beat_sec, { from, changes } = plan(p, ctx);
  const k = ctx.Springs.track(t, { from: from ? 1 : 0, changes, omega: ctx.Springs.fromSettle(0.3 * bs, 1), zeta: 1 }).value;
  const pct = (Math.max(0, Math.min(1, k)) * 100).toFixed(1);
  root.querySelector('.tag-bg').style.background = `color-mix(in srgb, var(--accent) ${pct}%, transparent)`;
  const box = root.querySelector('.tag-box');
  Object.assign(box.style, { color: `color-mix(in srgb, var(--surface) ${pct}%, var(--ink))`,
    transform: `scale(${1 - 0.03 * pressDepth(ctx, t, pressesOn(ctx, 'tag'))})` });
  const prev = box.querySelector('.tag-prev'), cur = box.querySelector('.tag-cur');
  if (prev) applyFade(prev, fade(ctx, t, -Infinity, ctx.t0));
  const same = ctx.continues && !prev;
  applyFade(cur, fade(ctx, t, same ? -Infinity : ctx.t0 + (ctx.continues ? 0.05 : 0.15) * bs));
}

export function hotspot(name, p, geo) {
  return name === 'tag' ? { x: Math.min(geo.w * 0.18, 60), y: 12 } : null;
}
```

What each part is doing:

- **`geometry`** sizes the shape from the props alone, with `textW` (a character-count estimate) rather
  than measuring the DOM, which does not exist yet. Keep `w` and `h` under 1400.
- **`plan`** is the state over time as data: where the row starts, and every change with its time.
  `render` and `endState` both read it, so they can never disagree.
- **`endState`** tells the next row of the same component where this one ended (after its presses).
- **`mount`** builds both the previous label (only when it changed) and the new one, stacked in one grid cell.
- **`render`** computes everything from `t`: the fill blend on a spring track, the press dip with
  `pressDepth`, the old label fading out at `ctx.t0` and the new one fading in just after.
- **`hotspot`** is where the cursor tip lands, as an offset from the shape centre; aim at the thing
  being pressed, a little off-centre so the pointer does not cover the text.

## The rules

These come from the tests and from review. Each one is here because breaking it showed up as a bug.

### 1. `render` is a pure function of `t`

Frames are rendered in parallel browser pages, in any order. Whatever `render` shows at `t` must depend
on `t` and the props only. So: no CSS `transition` or `animation`, no timers, no `Date.now()` or
`new Date()`, no `Math.random()`, and no variables written by an earlier frame. `mount` builds the DOM
once; `render` only sets styles, attributes and text.

Two tests enforce this: a scan of every component file for those words (`tests/contract.test.mjs`;
a fixed date like `new Date('2026-03-23')` is fine), and a browser run of every example and edge case
that seeks to each time from different starting points, compares the DOM, and fails if
`document.getAnimations()` is not empty (`tests/gallery.test.mjs`).

### 2. Row 0 is settled

A loop starts on row 0 and ends on a copy of it, so row 0 must already look finished at `t = 0`,
exactly like the last row does when the loop wraps. The engine gives row 0 `t0 = -1e6`, so anything you
time from `ctx.t0` (entrances, draw-ons, counts) is already done. If you time something another way
(for example from `ctx.beatT(ctx.row.at + 0.5)`), check `ctx.settled` and show it finished.

### 3. Continuations carry on; they do not replay

Two rows in a row with the same `use` are one component changing. For the second row `ctx.continues`
is true and `ctx.prev` holds the first row's end state. The engine does not fade the layer between
them; it swaps them exactly at `t0`, so your second row must start by looking exactly like the first
row ended:

- start every animated value from `ctx.prev` (the toggle starts from `prev.on`, the counter rolls on
  from `prev.to`) and animate to this row's props;
- do not replay the entrance (no rise-in of content that is already on screen);
- crossfade content that changed, like `button` and `tag` do: build the old content too, fade it out
  with `fade(ctx, t, -Infinity, ctx.t0)` and the new one in with `fade(ctx, t, ctx.t0 + 0.05 * beat_sec)`.

`tests/harness.mjs` has `noFlash`, which checks this for you: a press in row A, a continuation row B
that writes the pressed result, and B must match what A ended on.

### 4. State changed by a press goes in `endState`

If a press changes something (a toggle flips, a tab is chosen, a slider is dragged), export
`endState(props, ctx)` returning the props as they stand after the presses. The next row of the same
component reads it as `ctx.prev`. It may add private keys starting with `_` (the player's `_written`)
that only that next row reads. Keep it pure: it is called with the row's own `ctx`.

### 5. Hover comes from `ctx.targets`, never from cursor distance

A component reacts to hover when a cursor row is aimed at its hotspot, not when the cursor happens to
pass close by (the cursor crosses things on its way to somewhere else). Read the latest entry at or
before `t`:

```js
const aim = ctx.targets.filter((e) => e.t <= t).at(-1);
const i = aim?.target?.startsWith('avatar:') ? Number(aim.target.slice(7)) : -1;   // -1: aimed elsewhere
const since = aim?.carried ? -Infinity : aim?.t;   // a carried aim is already settled
const k = i >= 0 ? prog(ctx, t, since, 0.5) : 0;   // how far the hover has come in
```

A continuation's list starts with the previous row's aim, re-timed to `t0` and marked `carried`, so a
hover holds across the row change. `line-chart` (points) and `avatar-stack` are the references.
`ctx.cursorAt(t)` is only for following the pointer during a drag (`slider`, `player`).

### 6. Periodic motion uses `loopPeriod`

Anything that repeats (a spinner, a pulse, a caret blink, bouncing bars) takes its period from
`loopPeriod(ctx, seconds)`, which trims it so a whole number of cycles fits the loop and the seam
matches. Run it off the absolute clock `t`, not from `t0`, so it carries on unbroken into a
following row of the same component:

```js
const period = loopPeriod(ctx, 0.8);                 // about 0.8 s a turn
const angle = ((t % period) / period) * 360;
```

### 7. Presses dip with `pressDepth`

`pressDepth(ctx, t, pressesOn(ctx, 'tag'))` is 0..1 and follows the cursor's press kinds with the same
timing as the pointer: `true` dips and recovers, `'down'` dips and holds, `'up'` lets go. Scale the
pressed element by `1 - 0.03 * depth`. A drag (`'down'` then `'up'`) never spans a row change.

### 8. Colours are theme roles

Use the roles `canvas surface ink muted accent` (`'accent'` from `geometry`, `var(--accent)` in CSS,
`color-mix(in srgb, var(--accent) N%, transparent)` for tints). Never hex, never gradients or glows.
`pos` and `neg` (success and danger) are optional in a theme, so always fall back:
`role(ctx, 'pos', 'accent')` for a role name, `cssRole(ctx, 'pos', 'accent')` for CSS.

### 9. Design size, type and icons

Everything is in design pixels at a 1440 stage (the engine scales bigger stages). Type scale:
label 34/500, body 28/400, small 22/500, caption 18/500 uppercase with `letter-spacing: .08em`,
figure 72/600 with `font-variant-numeric: tabular-nums`. Two floors: 18 px is the smallest text a
component may use at all (captions only), and 22 design px is the legibility bar for anything a
viewer must read (body copy, labels, values). Icons come from
`icon(parent, name, size)` (24-unit grid, stroke 2, round caps): one stroke weight everywhere.
Springs only, through `ctx.Springs` and the helpers; position and size springs have zeta 1.

### 10. Props, class names and copy

- Prop names must not be reserved row keys: `at use name w h r fill ink shake badge` (the contract test fails).
  Every row accepts these whatever its component (the Row keys table at the top of `CATALOG.md`): `at`, `use`,
  `fill` and `ink` (a theme role or `#rrggbb`, overriding what `geometry` returns), `w`/`h`/`r` (overriding the
  shape's size), `shake: true` (error shake on arrival) and `badge: <n>` (count bubble); `name` is a custom
  hand-built state instead of `use`. The engine applies them; your component only sees the result in `ctx.geo`.
- Prefix class names with a short tag of the component (`tag-bg`, `tg-knob`) and keep them stable; tests select on them.
- Placeholder copy is neutral and made up: "The Placeholders", "Sam Rivera", "Desk lamp". No real
  artists, brands or people.

### 11. `meta` is complete

`useWhen` and `motion` are what Claude reads to choose and trust your component, so write `motion`
as what a viewer sees, including what presses and continuations do. `example` must be a single-line
`{ at: 0, use: '<name>', ... }` literal (the catalog and tests evaluate it). `edgeCases` should cover
empty text, very long text and the most items you allow. A family hotspot (`'item:<label>'`) needs a
`hotspotExample` naming a real one, so the contract test can resolve it.

## Helpers (`components/core/helpers.js`)

| Helper | Use |
|---|---|
| `el(parent, tag, attrs, text)` | make an element (`'svg:path'` for SVG) |
| `frame(layer, cls, w, h, top)` | a fixed design-size box, centred, so content keeps its layout while the shape morphs |
| `textW(text, size, weight)` | text width estimate for `geometry` |
| `prog(ctx, t, t0, settleBeats, zeta)` | 0 to 1 spring progress released at `t0` |
| `fade(ctx, t, tIn, tOut)`, `applyFade(el, f)` | a sub-element's enter (rise 12 px, unblur) and fast exit |
| `drawOn(ctx, t, t0, beats)` | 0 to 1 for drawing a stroke on |
| `landed(k)` | progress for a counted number, so it lands exactly on its value |
| `fmt(n, { decimals, prefix, suffix })` | number formatting (tabular, no -0) |
| `role`, `cssRole` | an optional theme role with a fallback |
| `icon(parent, name, size)` | an icon from the shared set (`ICONS`) |
| `pressesOn(ctx, prefix)`, `pressDepth(ctx, t, presses)` | presses on a hotspot or family, and the dip |
| `edges(ctx, from, changes, t, settle, n, lead)` | a two-edge travelling indicator (tabs, dock, toggle); `settle` is in SECONDS (`k * ctx.beat_sec`) |
| `loopPeriod(ctx, sec)` | the period for anything periodic |
| `plotLine`, `morphLine`, `resample`, `pathD` | line charts: plot a series, morph one series into another, make an SVG path |

## Ship it

From the `motion-video` folder:

```bash
node scripts/build_catalog.mjs                        # regenerate components/index.js and CATALOG.md
node scripts/gallery.mjs '' --only tag --stills       # write components/docs-images/tag.png
```

Then **look at the thumbnail** (open `components/docs-images/<name>.png`; Claude: Read the image).
It is a settled frame of your `example`. Fix anything clipped, cramped, off-centre or hard to read,
and re-run both commands. `node scripts/gallery.mjs OUT` (without `--stills`) writes a whole project
to `OUT` that plays every component and edge case, to watch with `render.mjs OUT --serve`.

Last, from the repo root:

```bash
npm test
```

It fails if the catalog is stale or a thumbnail is missing, and runs the contract, purity and
gallery tests on your component. For anything with presses or continuations, add a browser test
next to the others in `tests/components-<group>.test.mjs` using `scene` and `noFlash` from
`tests/harness.mjs`.
